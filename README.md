# Personal Site

A small static personal website with a home page, a publications page kept in
sync with Google Scholar, and a resume page that's also exported as a
downloadable PDF. A GitHub Actions workflow re-fetches publications and
rebuilds the site on a schedule, so it stays current without manual work.

## How it fits together

- `data/profile.yaml` — your bio, education, experience, skills, links. Edit by hand.
- `data/publications.json` — publication list. Auto-generated by
  `scripts/fetch_publications.py`; don't edit by hand.
- `templates/` — Jinja2 HTML templates for the site pages and the PDF resume.
- `static/` — CSS (and any images) copied as-is into the built site.
- `scripts/fetch_publications.py` — pulls your Google Scholar publications into `data/publications.json`.
- `scripts/build.py` — renders the templates + data into `docs/` (the folder GitHub Pages serves) and generates `docs/resume.pdf`.
- `.github/workflows/build.yml` — runs both scripts weekly (and on every push to `main`), commits the results, so the live site updates itself.

## One-time setup

1. **Fill in your details** in `data/profile.yaml`: name, bio, education,
   experience, skills, social links, and your Google Scholar `scholar_id`
   (the value after `user=` in your Scholar profile URL).

2. **Install dependencies locally** (optional, for local preview):
   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```
   WeasyPrint (used for the PDF) needs system libraries. On Debian/Ubuntu:
   ```bash
   sudo apt-get install libpango-1.0-0 libpangocairo-1.0-0 libgdk-pixbuf2.0-0 libffi-dev shared-mime-info
   ```
   On macOS: `brew install pango`.

3. **Build locally** to preview:
   ```bash
   python scripts/fetch_publications.py   # writes data/publications.json
   python scripts/build.py                # writes docs/
   python -m http.server -d docs 8000     # open http://localhost:8000
   ```

4. **Push to GitHub**:
   ```bash
   git add -A
   git commit -m "Initial site"
   git remote add origin <your-repo-url>
   git branch -M main
   git push -u origin main
   ```

5. **Enable GitHub Pages**: in the repo's Settings → Pages, set the source to
   "Deploy from a branch", branch `main`, folder `/docs`.

6. **(Recommended) Add a SerpApi key** so scheduled fetches in CI actually
   succeed. Google Scholar aggressively blocks scraping from datacenter IPs
   (including GitHub Actions runners), so the `scholarly` package often gets
   blocked there even though it works fine on your own machine. To avoid
   that: get a free key at https://serpapi.com/, then add it as a repo
   secret named `SERPAPI_KEY` (Settings → Secrets and variables → Actions).
   The fetch script automatically uses SerpApi when that secret is set, and
   falls back to `scholarly` otherwise.

Once set up, the workflow runs every Monday and on every push to `main`,
re-fetching publications, rebuilding the site and PDF, and committing the
result — so the live site and CV stay in sync with your Scholar profile
automatically.

## Notes

- If a scheduled fetch fails or is blocked, the workflow leaves the existing
  `data/publications.json` untouched rather than wiping the site's content.
- To change the update frequency, edit the `cron` schedule in
  `.github/workflows/build.yml`.
